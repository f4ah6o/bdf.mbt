# 共通テキスト baseline と描画・選択座標の契約を調査する

## 概要

異なる baseline 基準を持つテキストについて、描画、文字抽出、選択矩形、ヒットテストが同じ座標契約に従うかを合成入力で調査する。

## 背景

利用側から、top 基準で配置された文字と alphabetic 基準を仮定する選択領域がずれるとの報告がある。フォントサイズの固定比率による位置補正はフォントメトリクスに依存するため、共通仕様の代替にはならない。

登録時の main は e66fcce9645791c3b83a500083a9c171034f98b3。これは利用側報告に基づく調査課題であり、登録時点で最新 main 単体での根因再現や全形式への影響は確認していない。

## 問題

baseline 情報をどこで保持・正規化するかが利用側にとって明確でなく、表示と選択に別の基準が使われる可能性がある。描画だけを修正すると選択がずれ、利用側補正を残したまま共通側を変更すると二重補正になる可能性がある。

## 目標

描画と文字抽出・選択で必要な baseline 契約を特定し、既存契約の利用方法、共通側の不足、利用側の誤用を分離する。

## 対象外

- 特定の私有形式・利用側アダプターの実装。
- 実文書や組織情報の公開、フォントの無断再配布。
- 全形式の文字組版やクリップボード API 全体の刷新。
- 固定係数での位置合わせを恒久仕様として採用すること。

## 提案する方針

1. 同じ文字列を top と alphabetic の基準で配置した最小合成 BDF を用意する。
2. baseline 指定から display list、文字抽出、ブラウザー選択までの情報伝達を追跡する。
3. 日本語・欧文とフォールバックで、実フォントの描画範囲、選択矩形、ヒットテスト結果を別々に測定する。
4. 複数行・複数ページ・倍率・DPR を変え、基準変換の位置と互換性を決める。
5. 根因を確認した場合だけ、独立した実装修正と利用側の補正撤去手順に分割する。

## 受け入れ条件

- [ ] main・パッケージ版・ブラウザー・フォント・実行条件を固定して再現結果を記録する。
- [ ] baseline 情報の保持または正規化箇所を特定し、描画と選択の契約を明記する。
- [ ] 日本語・欧文・フォールバックで描画と選択の誤差を測定し、許容誤差を明示する。
- [ ] 未再現、利用側の誤用、共通側の不足を区別する。
- [ ] 共通側を変更する場合の二重補正回避と既存文書への影響を整理する。

## テスト計画

- 再配布可能なフォントを使い、ロード完了を待って合成入力を描画する。
- 倍率 0.75 / 1 / 1.5、DPR 1 / 2、複数行・ページで比較する。
- 文字画素、選択矩形、ドラッグ選択、コピー結果をそれぞれ検証する。
- フォント欠落や未実行条件を成功扱いにしない。
- 既存の選択・コピー回帰を維持する。

## リスク

フォント固有の余白と baseline 不一致を混同する可能性がある。座標契約変更による既存文書の位置変化と、利用側の二重補正に注意する。
