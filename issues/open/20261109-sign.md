# sign の移植: BDF 文書の署名と検証

## 概要

上流 `sign`（736 行）を移植し、BDF 文書の CMS SignedData 署名と検証を実装する。

## 背景

上流は RFC 5652 の CMS SignedData と X.509 証明書で、マニフェストの JCS（RFC 8785）と各パーツの SHA-256 に署名する。`crypto` は SHA-256 と ECDH を持つが、ASN.1 エンコーダと X.509 パーサは無い。

## 問題

署名と検証の API が無い。

## 目標

BDF 文書に署名を追加し、検証できる。

## 対象外

署名の信頼性判断。上流も「変更を見つけるが真偽は語らない」と明記している。

## 提案する方針

ASN.1 DER エンコーダとデコーダを `sign` 内に追加する。JCS を実装する。CMS SignedData を組み立てる。

## 受け入れ条件

- [ ] JCS が RFC 8785 のテストベクタを通る
- [ ] 署名を追加し、検証できる
- [ ] 改竄された文書の検証が失敗する
- [ ] `moon test --target js`、`--target wasm-gc`、`--target native` が green

## テスト計画

- `moon test --target js`
- `moon test --target wasm-gc`
- `moon test --target native`
- RFC 8785 のテストベクタ
- 上流 fixture の署名付き文書を検証する

## リスク

ASN.1 と X.509 は新しい表面。`crypto` の既存 API と衝突しないよう配置を決める。
