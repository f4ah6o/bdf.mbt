# Browser demo

The demo displays the upstream BDF project's 20-page homepage document. The
sample was generated once from `site/demo/demo.pdf` at upstream commit
`4f9af52dca60be1eb0daade39f7dc41d6a1fe431` with:

```sh
go run ./cmd/bdf generate -q site/demo/demo.pdf upstream-demo.bdf
```

The checked-in BDF sample has SHA-256
`e1cab46517eb3f0b1a4f2aeb4a5d0037e99161c4a1b77017f0c0903439608deb`.
The matching source PDF is `samples/upstream-demo.pdf` (742 KB, 20 pages),
also from the upstream MIT-licensed demo. It is used by the benchmark harness.
The 20-page sample is converted ahead of time; the demo also converts PDFs
in the browser, including an encrypted sample (password `demo`) and a feature
showcase with tiling patterns, JPX/JBIG2 images, Type3 glyphs and a form-field
URI action. Rendering and CSV, XLSX, DOCX, PPTX, image, font specimen, PDF,
draw.io and Parquet conversion in the demo use the
MoonBit JavaScript target, without a Go or WebAssembly runtime. Files chosen
by the user are handled in the browser. The sample contains Liberation fonts
([OFL](licenses/Liberation.txt)), IPA Gothic ([IPA Font License](licenses/IPA.txt)),
and WenQuanYi Zen Hei ([GPLv2](licenses/WenQuanYi.txt), with the font embedding
exception and copyright notice in its [README](licenses/WenQuanYi-README.txt)).

The gallery samples are the upstream MIT-licensed files, byte for byte:
`samples/basic.docx`, `basic.pptx`, `basic.xlsx`, `features.xlsx`,
`basic.csv`, `basic.md`, `cairo-cff.pdf` and
`images-jpx-jbig2.pdf`. The PowerPoint card opens `basic.pptx`, the Word
card `basic.docx` and the Markdown card `basic.md`. The previews
`previews/docx.png`, `previews/markdown.png` and `previews/pptx.png` were
rendered from these upstream files by the MoonBit native converter Worker.

The upstream sample card and the converter page also open the upstream PDF
fixtures verbatim: `chrome-doc.pdf`, `chrome-slides.pdf`, `chrome-masks.pdf`,
`cjk-cmaps.pdf` and `weasyprint-webfonts.pdf` (`converter/pdf/testdata`),
and `samples/features.pptx` (`converter/pptx/testdata`). They are
known-gap samples: the converter draws them, but tagged structure and some
masks still differ from upstream, as recorded in `docs/parity.md`.

`samples/upstream-report.pdf` (`examples/sample-files`) and
`reportlab-master.pdf` open too. Their PDFs ship a TrueType program that
Chrome's `FontFace` rejects as it is, so the converter rewrites an embedded
face through the shared sfnt writer before storing it as a BDF font part.
`reportlab-mixed.pdf` and `reportlab-type1.pdf` are checked in and
hash-pinned without a card.

Run `node demo/verify-samples.mjs` to check the SHA-256 of every upstream
sample against the hashes recorded in the script.

A sample whose subset the MoonBit converter does not support yet (for
example the embedded fonts of `cairo-cff.pdf`) reports an explicit
error instead of drawing a wrong page.

The page also has a round-trip section for the document currently in the
viewer. **PDF** embeds the used fonts and keeps URI links; **Markdown** keeps
headings, lists, tables and images; **テキスト** returns the same page records
as the upstream search-text tool; **MiniSearch** indexes those records in the
browser (MiniSearch is MIT licensed, see
[licenses/MiniSearch-MIT.txt](licenses/MiniSearch-MIT.txt)). The PDF writer
approximates gradients with their darkest stop and omits masks, filters and
images; tagged PDF structure is not implemented yet. These limits are shown as
warnings under the PDF result.

The viewer draws a radial gradient (PDF shading type 3) inside a group as a
flat disc: Canvas 2D loses the inner colour of a radial gradient created on a
scaled group canvas. The BDF paint and its coordinates match upstream, so this
is a viewer limitation, not a conversion one; `chrome-slides.pdf` shows it on
its first slide. See `docs/parity.md`.

The [wasm-gc page](wasm-gc.html) runs the same PDF→BDF and BDF→PDF/Markdown/
text/MiniSearch operations in a WebAssembly GC module. It needs a browser with
wasm-gc and JS string builtins (current Chrome or Edge). Files are still handled
locally; the module is loaded only when a conversion or export starts.

The benchmark panel is generated by `npm run bench:demo`. The harness runs
the checked-in `samples/upstream-demo.bdf` and `samples/upstream-demo.pdf`
through both the JavaScript and wasm-gc bridges, measures a 2-run warm-up and
7 iterations, and writes `demo/benchmarks.json`. The page fetches that file and
shows the median times, input/output sizes and measurement environment. Re-run
the harness after changing an export path and commit the updated JSON.

The same table shows the upstream BDF Go implementation. Build the upstream
CLI with Go 1.27 and point `bench:upstream` at the binary:

```sh
git clone https://github.com/shibukawa/bdf /tmp/shibukawa-bdf
(cd /tmp/shibukawa-bdf && go build -o /tmp/bdf-go ./cmd/bdf)
npm run bench:upstream -- --bdf /tmp/bdf-go --revision "$(git -C /tmp/shibukawa-bdf rev-parse --short HEAD)"
```

This measures the upstream CLI's `pdf`, `markdown`, `text` and `generate`
commands on the same 20-page BDF/PDF and writes
`demo/benchmarks-upstream.json`. Process startup and file output are included;
the upstream values are therefore a CLI comparison, not an in-process
microbenchmark.

The STIX Two Text sample is from the existing `compat/font/fixtures/stix.ttf`
fixture; copyright and SIL Open Font License 1.1 terms are included in
[STIX-OFL.txt](licenses/STIX-OFL.txt). The demo tests TTF and WOFF2 input.
The upstream project and demo source are distributed under the
[MIT license](licenses/BDF-MIT.txt).

Build and test locally:

```sh
moon update
npm ci
npx playwright install chromium
npm run build:demo   # JS build, wasm-gc export bridge, demo assets
npm run test:demo
npm run test:export   # export tabs, benchmark table and the wasm-gc page
npm run bench:demo    # re-measure and rewrite demo/benchmarks.json
npm run bench:upstream -- --bdf /tmp/bdf-go   # upstream Go column
python3 -m http.server --directory _build/pages 8000
```

The test serves the site under `/bdf.mbt/`, exercises all sample pages and the
converter page, search, navigation, downloading, CSV and SVG conversion, TTF
and WOFF2 font specimens, PDF, encrypted PDF password retry, the PDF feature
showcase, DOCX, PPTX, draw.io and Parquet conversion, view selection and
saving, unsupported files, XLSX input, and mobile layout. `test:export` checks
the PDF/Markdown/text/MiniSearch tabs, the checked-in benchmark table, the
wasm-gc page, PDF→BDF conversion in wasm-gc, and 375 px horizontal overflow. An XLSX fixture is
also rendered in Chromium and each sheet is compared pixel-for-pixel with its
upstream Go-generated BDF using the same viewer. This checks that fixture, not
every Excel feature. The test requires Playwright Chromium. Run the `vlmkit`
gates against the served URL for markup and accessibility checks.

The `Demo pages` workflow builds and tests the site on pull requests and pushes
to `main`; manual runs work from `main`. It deploys only from `main` if the
repository's Pages source is already set to **GitHub Actions** and the
`github-pages` environment already exists. It uses that environment and its
protection rules without changing repository settings or creating an
environment. If Pages is disabled, an administrator can choose **Settings →
Pages → Build and deployment → Source → GitHub Actions**, then run the workflow
again from the Actions tab. GitHub reports the resulting site URL in the
workflow's deployment step. The expected default project URL is
`https://f4ah6o.github.io/bdf.mbt/`.

The Excel cards open the upstream `converter/xlsx/testdata/basic.xlsx` and
`features.xlsx` fixtures; CSV, Word, PowerPoint, Markdown, PDF, SVG and
Parquet samples come from `examples/sample-files`, `converter/pdf/testdata`,
`image/svg/testdata` and `converter/parquet/testdata`. They are distributed
under the upstream MIT license. The demo converts the supported subset;
when a font directory is supplied it uses the first face for metrics and
embedding, otherwise it falls back to estimated metrics.
