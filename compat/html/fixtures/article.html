How Canvas Documents Load Quickly

By Alex Example · September 20, 2026

Previews of office documents used to mean a server that rendered every page into an image. The images were large, text could not be selected, and every zoom level needed another round trip. Drawing the document in the browser itself changes all three: the file holds drawing instructions, and the browser's own font and image code does the rest.

The instructions map one to one onto the methods of CanvasRenderingContext2D, so the decoder is a loop that reads bytes and calls the context. There is no layout engine in the viewer; lines are broken once, when the document is converted, with the metrics of the fonts that are then embedded.

What goes into a document

A document is a set of parts named by the hash of their content. Masters, headers and repeated pictures are stored once, because the same bytes get the same name.

  • Objects: drawing instructions for pages, strips and tiles.
  • Fonts: subsets in WOFF2, loaded with FontFace.
  • Images: PNG, JPEG, WebP and AVIF, decoded with createImageBitmap.

Tables keep their structure for screen readers, with headers that span columns:

The fastest code is the code the browser already has.

Trying it

Convert a file on the command line and open the result in the viewer:

bdf generate report.docx report.bdf
bdf split report.bdf out/

The same converter runs in a Web Worker as WebAssembly, so a file dropped on the page never leaves the machine. Read the specification for the details, or go back to the list of parts.
