# XLSX picture rendering regression

This test samples the existing Go-produced `picture-formats.json` fixtures at indices 8, 12, 16, 20 and 24: one embedded GIF, BMP, WebP, AVIF or SVG per sheet. It compares the Go BDF rendered by the upstream JavaScript renderer with (1) the MoonBit XLSX conversion rendered by upstream and (2) the MoonBit conversion rendered by the MoonBit browser sheet renderer. This reuses the same fixture and VLMKit/Playwright comparison approach as the XLSX table visual work; it does not duplicate that work or the demo test.

The media file records the original fixture images, MIME types and expected intrinsic dimensions. The browser must decode each image, verify its natural dimensions and find those exact bytes in the BDF. Each canvas and captured case must have colored pixels in the picture area, and VLMKit captures must match exactly at its three viewports. The comparison therefore detects changes in placement, displayed size and visible image pixels relative to the Go BDF in this Chromium environment. Output and failure artifacts are stored under `_build/visual-diff/`.

Run `moon build --target js`, install Chromium using Playwright, then run `node compat/xlsx/picture-visual-compare.mjs`. The GIF fixture is animated; the browser canvas captures a frame, so timing-dependent frame differences are possible and should be diagnosed from the saved captures. This is a sample against upstream, not Excel, and does not establish compatibility for arbitrary images, other browsers, multiple images, cropping, or effects. The separate compatibility documentation describes the broader current conversion scope.
