# Parquet writer compatibility

The fixtures are generated by the upstream Go Parquet writer at commit
`4f9af52dca60be1eb0daade39f7dc41d6a1fe431`. They exercise empty tables,
all supported value types, nulls, dates outside Go's duration range, wide
schemas, a multi-page column, and CSV-to-Parquet integration.

From that upstream checkout, regenerate the fixture with:

```sh
go run /path/to/bdf.mbt/compat/parquet/generate.go > /path/to/bdf.mbt/compat/parquet/upstream.json
```

Run `moon build --target js` and `npm run test:parquet-compat` to compare
the MoonBit output with the Go writer byte for byte.

The MoonBit writer deliberately fixes an upstream data loss bug: when a page
reaches the 1 MiB value limit before 65,536 rows, it continues from the next
unwritten row. The Go writer skips the rest of that 65,536-row block.
