## Survivor classification

All four baseline survivors were real gaps, not equivalent mutants. None was
left alive and none was reclassified to raise the score.

| Survivor | Why it survived | Test that kills it |
| --- | --- | --- |
| `55:13` `\|\|` → `&&` | `lo < 0 && hi != 0` is false whenever `lo >= 0`, so a nonzero high word was silently accepted. No test fed a high word. | `u64_size rejects a nonzero high word` |
| `89:15` `\|\|` → `&&` | `size < 0 && size > remaining` can never hold, so a negative skip was accepted and moved `pos` backwards. No test skipped a negative size. | `skip rejects out-of-range sizes` |
| `135:19` `&&` → `\|\|` | `c >= 48 \|\| c <= 57` is always true, so the enclosing `(...) \|\| (c >= 97 && c <= 102)` is always true and `!` is always false: **every 32-byte string is accepted**. A positive assertion cannot see this. | the negative assertions in `valid_hash accepts only 32 lowercase hex characters` (`g`, uppercase, `:`) |
| `135:43` `&&` → `\|\|` | `c >= 97 \|\| c <= 102` is always true, so the same OR makes every 32-byte string valid. Again only a negative assertion can see it. | the negative assertions in `valid_hash accepts only 32 lowercase hex characters` |

`core/bytes_test.mbt` adds 17 tests: 13 unit tests over `Reader` bounds,
`u64_size`, `varuint`, `skip`/`take`, `hash`, `f32` and `valid_hash`, plus 4
QuickCheck properties. The core package went from 81 to 98 passing tests.

The properties are written to avoid restating the implementation:

- `take` splits the input at a generated point and checks the returned prefix,
  the remaining length, and the suffix taken afterwards.
- `hash` pads or truncates the generated bytes to exactly 16 and compares
  against an independent digit-table hex oracle, not the arithmetic in
  `Reader::hash`.
- A separate property checks only that `hash` output has valid hash *format*,
  so the circular `hash` → `valid_hash` check is no longer the only hash
  property.
- `valid_hash` rejects every non-32-character string.

## Limits

- **Seven mutants is a slice, not a score.** The default operator set produces
  56 mutants for this file. `comparison`, `arithmetic`, `literal` and
  `condition` were not measured in the before/after pair.
- **Two wider runs were aborted, and are kept as diagnostics, not results.**
  - `.turtles-artifacts/partial-56/`: default operators, 56 mutants, `--jobs 4`.
    Stopped at 12/56 (9 killed, 3 survived) after ~4 minutes; no `report.json`
    was written, so it has no score.
  - A `comparison,boolean` run (25 mutants) was started twice and killed by
    transport disconnects before any mutant completed. No artifact survived.
- **The oracle is module-wide and slow.** Each mutant recompiles `core` and its
  60 dependents and runs 2746 tests, so a mutant costs 29–51 s. `--affected`
  was not used: it is experimental and would still select most of the module.
- **`moon install` was not usable.** `~/.moon` is read-only here, so the
  registry cache lock fails. The checksum-verified v0.4.7 release asset was
  installed into `bin/` instead.
- **`moon fmt --check` fails on this worktree for pre-existing reasons.**
  Unrelated files such as `convert/all/all_wbtest.mbt` are already unformatted
  at `77204ba`. The files added here do not appear in that diff.
- **actrun verifies this pilot through its own local workflow, not the
  integration checkout's `verify.mjs`.** That script hard-codes `REPO_ROOT` to
  its own tree, exposes no `--root`/`--worktree` option, and its gate list
  (`self-test`, `workflow-lint`, `ci/test`, `ci/demo`, `parity`, `visual`,
  `site`, `pages/*`, `hosted/setup`) contains no pilot gate, so it is not
  reusable here. The runner binary itself is reusable: this worktree ships
  `.github/local/turtles-pilot.yml` and actrun executes it directly. Nothing
  ran on hosted Actions.
- **actrun's `if:` cannot see process environment variables.** A job gated on
  `if: ${{ env.TURTLES_MUTATE == 'true' }}` is skipped even when the variable
  is exported in the calling shell; a probe workflow confirmed the variable
  reaches `run:` steps but not the `if:` context. The opt-in audit and mutation
  runs are therefore separate workflow files that are invoked explicitly,
  rather than gated jobs that would silently never fire.
- **`test-import` is not supported by moon 0.1.20261104.** `moon test` fails
  with `Failed when discovering packages`, so `moonbitlang/core/quickcheck` is
  a regular `import` in `core/moon.pkg`. It is used only by test files.
- **The 23 modified `pkg.generated.mbti` files are not part of this patch.**
  The worktree was clean at `77204ba` when this pilot started; these files were
  rewritten by the `moon check` runs this pilot performed. They are kept on
  disk rather than discarded, but the intended change is `core/moon.pkg`,
  `core/bytes_test.mbt`, `scripts/turtles-ratchet.mbtx`, the two docs, and the
  `.gitignore` entries for `bin/` and `.turtles-artifacts/`.

## Completed wider probe and follow-up (2026-11-11)

The default five operator groups were measured over all 56 mutants in
`core/bytes.mbt`, with `--target js --jobs 4 --timeout 240` and module-wide
checks/tests. `.turtles-artifacts/expanded-final/report.json` records **54
killed, 2 survived, 0 timeout, 0 unviable, 96.428571%**. This is a final-only
wider probe, not a paired improvement score. The recorded start/end span is
approximately 29m50s (the start marker was written just after launch).
Temporary workspaces/builds peaked around 14 GB; free disk went from 53 GB
to 39 GB and recovered to 52 GB after turtles removed its temporary tree.

The two survivors were investigated separately:

- Removing the fifth-byte overflow guard at `bytes.mbt:72` is a real test
  gap: `80 80 80 80 10` loses its excess bits in a 32-bit shift. A new exact
  `BadFormat` regression now rejects this input. The pristine core suite
  passes 99/99; temporarily applying that exact mutant makes the new test
  fail (98/99), and restoring the original source returns to 99/99. See
  `expanded-regression-{pristine,mutant,restored}.log`. Production source was
  restored byte-for-byte to HEAD. There are now 18 added tests, including
  the earlier four properties.
- Removing the subsequent `value < 0` check at `bytes.mbt:77` appears
  equivalent for the existing implementation: the preceding guard limits
  the fifth byte to 0..7, while earlier payloads contribute only seven bits
  each, so the accumulated value cannot set bit 31. This is a reasoned
  equivalence assessment, not a proof-tool result. No exclusion was added
  and the source guard was retained.

**The 56-mutant report predates the last regression.** Its score remains
54/56. Only the newly covered survivor was replayed directly after that
addition; do not describe the current tree as a completed 55/56 turtles run.
The earlier 7-mutant paired reports likewise retain their original test
fingerprints and numbers.

Independent review of the ratchet is resolved. It checks fixed identities,
unique rows, path/operator scope, outcome/count consistency and recomputed
score. This fixed pilot additionally rejects any UNVIABLE mutant rather
than allowing compilation failures to inflate the score. The repeatable
fixture suite passes 9/9, including consistent-count/wrong-score and six
or seven UNVIABLE cases. The actual saved 7/7 report also passes check-only.
Logs: `ratchet-review-verification.log` and `ratchet-actual-report.log`.

Recommendation: retain the small boolean ratchet and the added regression
coverage, then broaden selectively by changed parser helpers. Do not turn
this evidence into an all-repository per-change mutation gate yet: the
wider single-file run cost roughly half an hour and 14 GB of temporary
storage. Neither completed run showed a property-only kill, so it does not
establish a unique advantage for PBT over the accompanying unit tests.
No commit, push, hosted Actions run or main-branch integration was performed.

## Local actrun route

`.github/workflows`, so GitHub never discovers it, and its only trigger is
`push: branches-ignore: ['**']`, which no branch satisfies. actrun uses the
workflow file's directory as the workspace, so the job sets
`working-directory: ../..`. The current workflows inherit caller `MOON_HOME`
or Moon's normal HOME-based default; they do not force a private cache path.

Three files, all outside `.github/workflows`:

`core/container_test.mbt` adds 4 tests (3 unit, 1 QuickCheck property) that
build a single-file BDF and vary the declared part length.

**Reachability analysis.** `parse_header` guarantees
`manifest_offset + manifest_length <= data.length()`, so `part_start >
data.length()` is always false. `parse_manifest` rejects `len < 0`, `size < 0`
and `off < 0`, so `part.offset < 0` and `part.length < 0` are always false.
With `A`/`B`/`C` false and `D` = `offset > remaining`, `E` = `length >
remaining - offset`, the guard reduces to `D || E`, and `D` implies `E`
because `remaining - offset < 0 <= length`.

| Mutant | Verdict | Evidence |
| --- | --- | --- |
| `77:24` `A \|\| B` → `A && B` | **equivalent** | both operands always false |
| `78:23` `B \|\| C` → `B && C` | **equivalent** | both operands always false |
| `79:34` `C \|\| D` → `C && D` | **equivalent** | `C` false, and `D ⇒ E` so `D \|\| E ≡ E` |
| `80:48` `D \|\| E` → `D && E` | **reachable, killed** | differs when `D` false and `E` true: a part starting inside the file but extending past it |

The three remaining survivors are equivalent, not untested. No defensive code
was removed and no impossible test was written to raise the score.
